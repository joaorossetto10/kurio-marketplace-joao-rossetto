## Auditoria de arquivos e segurança

- Apenas o README original estava rastreado no commit `fea4e7c`; os arquivos da solução estão locais e precisam ser adicionados ao repositório próprio após autorização. `node_modules`, `dist`, `test-results` e `playwright-report` estão ignorados. Os relatórios Lighthouse e quatro screenshots curados estão em `docs/`.
- `.env.demo` e `.env.example` contêm somente `VITE_ENABLE_MOCKS=true`. A varredura por padrões de chave privada, token GitHub, AWS e OpenAI não encontrou credenciais de produção nos arquivos de release. As senhas em documentação são exclusivamente das contas fictícias.
- A UI não importa fixtures ou stores; o único import de `src/mocks` fora do diretório de mocks é o bootstrap condicional. `localhost`/`127.0.0.1` aparece apenas em Vite, Playwright, instruções e relatórios locais; o cliente REST usa `/api` e o Socket.IO usa `window.location.origin`.
- O build contém `mockServiceWorker.js` na raiz, imagens e fontes locais. A configuração Vercel fixa `npm ci`, `npm run build`, `dist` e rewrite SPA. Isso ainda não comprova o comportamento do host remoto.
